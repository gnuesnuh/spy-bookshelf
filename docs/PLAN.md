# 기획서 — Books: 읽을 책 찾기 + 국내 전자책 확인 도구

작성 2026-11-13 · 개인용 · Claude Code와 함께 쓰는 작업 도구
관련 문서: `CLAUDE.md`(작업 규칙·명령), `docs/PROGRESS.md`(진행 기록·검증 수치)

## 1. 한 줄 정의
책 한 권이나 장르 하나를 말하면, 믿을 만한 추천 소스를 모아 다음에 읽을 책 목록을 만들고 **지금 한국어 전자책으로 읽을 수 있는지**까지 붙여 주는 개인용 도구.

## 2. 풀려는 문제
- 영미권·일본 추천(어워드, Reddit, 언론 결산)은 질이 좋지만 절반 가까이가 국내 미번역이고, 번역됐어도 한국어 제목이 원제와 달라 찾기 어렵다.
- 번역본이 있어도 어느 서점·구독 서비스(밀리, 리디셀렉트, 크레마클럽)에 있는지는 일일이 검색해야 한다.
- 다른 AI로 만든 기존 추천 시트는 형식은 좋지만 제목 오기, 미번역 도서를 번역됨으로 표기, 출처 오기가 섞여 있다 → **검증된 사실만 담은 목록**이 필요하다.

## 3. 사용자와 사용 방식
- 사용자: 본인 1명. 공개 서비스, 회원, 결제 없음.
- 실행 주체: **Claude Code**. 사용자가 "OO 같은 책 찾아줘"라고 말하면 Claude Code가 아래 흐름(6절)을 수행하고, 결과를 웹앱(주 화면)과 xlsx(보조)로 보여 준다.
- 공유 방식: 이 폴더(코드 + `CLAUDE.md` + `docs/`)를 다른 Claude Code 세션이나 다른 컴퓨터에서 열어도 같은 방식으로 이어서 작업할 수 있게 한다. 비밀키(`.env`)는 각자 발급해 넣는다.

## 4. 목표와 성공 지표
| 지표 | 현재 (2026-11-13) | 목표 |
|---|---|---|
| 국내판 매칭 재현율 (정답지 기준) | 94% (33/35) | 95% 이상 |
| 국내판 오매칭 | 0건 | 0건 유지 |
| 추천 범위 재현율 (시드 → 정답지 목록 포함률) | 68% (27/40, 팅커 테일러) | 80% 이상 |
| 출력 필드 충족 (시트 12개 열) | 12/12 | 유지 |
| 질의 1건 처리 시간 | 약 20~30분 (조사 포함). 국내 정보 부착은 약 7분 → 1분 안팎으로 단축 | 10분 이내, 목록은 먼저 표시 |
판정이 애매하면 표시를 남긴다(✅ 확정 / ⚠️ 유력 / ❓ 불명). 틀린 '가능'보다 '확인 불가'가 낫다.

## 5. 범위
**MVP (지금 만들 것)**
1. 입력 해석: 책 제목 → 원서·저자·장르 확정 / 장르 → 하위 장르 확정
2. 추천 후보 수집: 소스별 목록에서 언급 집계 → 기본 25권 (국내판 있는 책 우선, 미번역 명작은 별도 그룹)
3. 국내판 매칭(YES24 원제) + 서점·구독 입점 조회
4. 결과 화면은 웹앱(질의별 목록을 골라 보는 모바일 화면). 시트 형식 xlsx는 보조 출력
5. 정답지 기반 자동 채점

**MVP 이후**
- 리뷰 요약 자동화(수집 리뷰 → "왜 좋다는가 / 호불호 / 비슷한 책")
- 베이지안 보정 평점과 가중치 점수로 정렬
- 일본 소스(このミス, 本格ミステリ大賞, 読書メーター), 논픽션 소스(FT, Five Books, Open Syllabus)
- 도서관 정보나루 대출 데이터로 '국내 독자가 함께 읽은 책' 축 추가

**범위 밖**
- 공개 웹 서비스, 다중 사용자
- 서점 데이터 대량 수집·DB 축적·재배포 (YES24 약관 금지)
- Goodreads·Reddit 대량 스크래핑, 리뷰 원문 게시

## 6. 사용 흐름 (Claude Code 작업 절차)
1. **입력 확인**: 사용자 입력이 책인지 장르인지 판단. 책이면 YES24로 원서·저자 확정(`yes24_lookup.py`).
2. **소스 수집**: 장르에 맞는 소스를 WebSearch/WebFetch로 읽는다.
   - 공통: 장르 어워드 수상·후보작, Goodreads 목록·Choice 후보, 언론 결산(NYT·Guardian·Economist), Five Books 전문가 추천, Shepherd 유사 도서, 독자 커뮤니티(Reddit — 허용 도메인 필요)
   - 출처마다 실제로 연 페이지만 쓴다. 검색 스니펫만으로 수상 이력을 적지 않는다.
3. **집계**: 원제 기준으로 같은 작품을 묶고(시리즈는 대표작) 소스 수로 순위 → `data/queries/<slug>.rank.json`
4. **목록 작성**: 상위 후보에 카테고리, 수상·선정 이력(출처 확인분만), 추천 포인트를 붙여 `data/queries/<slug>.json`
5. **국내 정보 부착**: `python scripts/build_query.py <slug>` → 번역본·eBook·밀리·리디·크레마·평점
6. **검수**: ⚠️/❓ 항목과 '국내판 없음' 항목을 확인. 필요하면 저자 국내 출간 목록으로 재확인.
7. **전달**: `추천_<질의>.xlsx` + 요약(지금 바로 읽을 책, 미번역 명작)

## 10. 결정 사항
- 개인용으로 한정한다 → 약관 리스크를 최소화하고 공개 서비스 기능은 만들지 않는다.
- 국내판 매칭은 YES24 Open API를 주력으로 쓴다(알라딘 대체).
- 정답지는 기존 시트가 아니라 검수본 `gold.json`이다.
- 추천은 "소스 언급 집계"를 기본으로 하고, 출처를 확인한 정보만 쓴다.

## 11. 확정 사항 (2026-11-13)
- Reddit: 사용한다. 클라우드 IP는 403이므로 **사용자 PC에서** `scripts/reddit_fetch.py`로 공개 JSON 수집(요청서 `docs/requests/REQ-001`). 결과 파일만 분석에 쓴다.
- Reddit 대안(클라우드에서 바로 가능, 2026-11-13 확인): Hacker News(Algolia API, 비즈니스·기술·논픽션에 강함), Lemmy(lemmy.world API), Tildes. 차단: Ask MetaFilter, Wall Street Oasis, Bogleheads(403).
- 일본 커뮤니티: 読書メーター(자동 접근 거부), ブクログ(robots 금지)는 수집 불가. 대신 공개 랭킹(このミステリーがすごい!, 本格ミステリ大賞, 本屋大賞, 週刊文春ミステリーベスト10)을 위키백과 등에서 수집한다. 일본 소스는 MVP 이후 → 추리·장르소설 질의부터 적용.
- 목록 크기: 기본 25권.
- 미번역 도서: 포함하되 '미번역 명작' 그룹으로 분리 표시(원서로 읽을 후보).

## 12. 운영 방식: 구독으로 실행 (2026-11-13)
API 과금 없이 Claude 구독으로 운영한다. 공식 문서 확인 결과:
- 검색·소스 읽기·집계·요약은 Claude Code 세션이 수행한다(구독 사용량).
- 스크립트 안의 모델 호출은 Anthropic API 대신 `claude -p`를 쓴다. `ANTHROPIC_API_KEY`가 설정돼 있으면 구독보다 우선해 API로 과금되므로 설정하지 않는다. 브라우저 없는 실행은 `claude setup-token` → `CLAUDE_CODE_OAUTH_TOKEN`.
- 주기 실행은 예약 작업(routines)으로 한다. 구독 사용량에서 차감된다.
- 웹페이지에서 즉시 모델을 호출하는 실시간 추천은 하지 않는다(구독으로 불가, 정적 페이지에 토큰을 둘 수 없음). 추천은 "요청 → 세션/예약 작업이 처리 → 결과 JSON 커밋 → 웹앱 반영" 순서의 비동기 방식이다.
- Agent SDK에 구독 로그인을 쓰는 것은 문서가 권하지 않는다. 개인 스크립트는 `claude -p`를 쓴다.
