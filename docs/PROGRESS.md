## 1. 서비스 설계

### 1.1 추천 축
| 축 | 소스 | 역할 | 한계 |
|---|---|---|---|
| 전문가 필터 | 장르 어워드(CWA 대거, 에드거, 휴고·네뷸러, 퓰리처, 부커, 베일리 기퍼드), 논픽션은 FT 올해의 비즈니스 북 · Five Books | 바닥이 탄탄한 작품 | 평론가 취향, 난해한 작품 섞임 |
| 코어 독자 필터 | Reddit 추천 스레드, 독자 포럼, Goodreads 토론 | 숨은 페이지터너, "왜 재밌는지" 맥락 | 영미권 위주, 미번역 비율 높음 |
| 대중 검증 | Goodreads 평점 × 평가 수, YES24 평점 | 우선순위·정렬 | 자기계발서 평점 인플레 |
| 시의성 | 언론 연간 결산(NYT, 가디언, NPR, Economist) | 최근 3~5년 신작 | 연 1회 갱신 |
| 국내 역추적 | YES24 원제 매칭, 출판사 시리즈 | 지금 읽을 수 있는 책 | – |

논픽션 추가 신호: 교재 채택(Open Syllabus), Five Books 전문가 인터뷰. Amazon은 PA-API 종료로 실시간 리뷰 분석 대신 UCSD Amazon Reviews 2023 데이터셋(비상업·연구용) 오프라인 분석을 검토.

### 1.2 처리 구조 (5층)
1. 후보 수집 — 소스별 언급 집계
2. 동일 작품 묶기 — 원제·저자 기준 작품 ID (가장 중요, 틀리면 전부 틀림)
3. 메타데이터·리뷰 요약 — 리뷰 원문은 그대로 싣지 않고 "왜 좋다는가 / 호불호 / 비슷한 책"으로 재서술
4. 점수화 — 베이지안 보정 평점 `(v/(v+m))·R + (m/(v+m))·C` + 어워드·언급 가중치
5. 국내 판매 확인 — 번역본 → 전자책 → 밀리·리디셀렉트·크레마

### 1.3 입력 처리
- 장르 입력: 내부 분류로 변환 → 장르 DB 조회
- 책 제목 입력: 작품 확정 → '함께 언급됨'(같은 어워드 후보·같은 추천 목록) + '함께 읽힘' + 내용 유사도로 이웃 도서
- 출력 그룹: 🏆 검증된 수작 / 🔥 독자·큐레이터 강추 / 📈 대중 검증 상위 / 🆕 최근 화제작 / 🎓 고전 / 🇰🇷 지금 바로 읽기
- 운영은 실시간 크롤링이 아니라 미리 만든 추천 목록 + 조회 시점 국내 정보 부착 (YES24 정책상 대량 DB 축적 금지)

### 1.4 데이터 소스 결정 이력
- 알라딘 OpenAPI의 `originalTitle`로 설계 → 2026-08-31 종료 공지, 10-30 서비스 종료 확인 → **YES24 Open API로 교체** (원제·번역 여부·eBook 링크·평점·판매지수 제공, 즉시 발급, Basic 무료)
- 국립중앙도서관 ISBN API는 원서명 필드가 없어 매칭 주력으로 부적합
- Goodreads는 API 없음, 스크래핑은 약관·robots 논란 → auto_complete 평점 조회만 사용
- 구독 서비스(밀리·크레마)는 공개 API가 없어 build_data.py의 검색 조회 사용

## 9. 일본 소스를 질의에 연결 (2026-11-13)
8절의 첫 구현은 랭킹을 점수순으로 늘어놓기만 해서 '제목·장르로 추천받는다'는 구조와 맞지 않았다. `build_ja_list.py`를 질의 방식으로 바꿨다.
- **제목 질의** `--seed`: 기준 도서를 한국어 제목(YES24로 일본어 원제를 얻음)이나 일본어 원제로 랭킹에서 찾고, ① 같은 해 같은 랭킹에 함께 오른 작품 (11-순위)점 ② 같은 작가의 다른 진입작 3+0.3×(11-순위)점, 5권까지 ③ 앞뒤 3년 상위작 0.3×(11-순위)점. 예: `like-kokurojo`(『흑뢰성』) 25권 — 함께 오른 작품 7, 같은 작가 5, 비슷한 시기 12. 국내판 21권, 전자책 20권.
- **장르 질의** `--genre`: mystery(このミス·文春) / fiction(本屋大賞) / all.
- 같은 책이 여러 목록에 나오면 이미 만든 리뷰 요약을 재사용한다(`build_data._review_by_work`).
- 한계: 기준 도서가 랭킹 10위 안에 든 적이 없으면 제목 질의가 안 된다. 일본 소스와 영미권 소스를 한 목록에서 섞는 것은 아직 안 된다(영미권 집계가 코드화되지 않음).

## 11. 정정 (2026-11-13): 소스 캐시는 목록 생성기가 아니다
