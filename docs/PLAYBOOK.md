# PLAYBOOK — 책 제목 하나로 추천 목록 만드는 법

> 작성: 채팅(클라우드) 세션, 2026-11-13. 대상: 로컬 Claude Code.
> 『물고기는 존재하지 않는다』, 『문 앞의 야만인들』, 『블러프』 목록을 실제로 만든 순서를 그대로 적었다.
> 요약은 `docs/PLAN.md` 6절, 목록 이후(리뷰 요약·영상화·푸시)는 `CLAUDE.md` '새 추천 질의 순서'.

## 0. 핵심 원칙 다섯 개
1. **목록은 스크립트가 만들지 않는다. Claude Code가 근거를 읽고 판단해서 쓴다.** 스크립트(`award_candidates`, `community_fetch`, `gemini_candidates`)는 후보와 근거를 모아 줄 뿐이다.
2. **먼저 책의 성격(축)을 정한다.** 축이 틀리면 나머지가 다 정확해도 목록이 틀린다(5절 사례).
3. **근거는 실제로 연 페이지만.** 수상·선정 이력, 추천인 이름은 페이지에서 확인한 것만 적는다. 검색 스니펫·기억으로 적지 않는다.
4. **책마다 근거 수를 센다.** 여러 소스에 겹친 책이 위로 간다. 근거 1곳짜리는 축에 정확히 맞을 때만 넣는다.
5. **번역 여부는 목록을 만든 뒤 스크립트가 판정한다.** 목록 단계에서 한국어 제목을 추측해 적지 않는다(틀린 제목이 매칭을 망친다).

## 1. 단계 0 — 도서 성격 분석 + 의도 확인
기준 도서를 4개 축으로 나눈다.

| 축 | 질문 | 『블러프』 | 『문 앞의 야만인들』 |
|---|---|---|---|
| 소재 | 무엇을 다루나 | 포커 | 사모펀드 RJR 나비스코 인수전 |
| 주제 | 무엇을 말하나 | 불확실성 속 의사결정, 운과 실력 | 탐욕·자존심이 만든 기업 전쟁, 월가 권력 |
| 형식 | 어떻게 썼나 | 학자가 1년간 직접 도전한 체험기 | 내러티브 논픽션(소설처럼 읽히는 취재기) |
| 톤 | 읽는 느낌 | 지적·성찰적 | 스릴러 같은 긴장감, 냉소 |

축마다 "이 축으로 가면 어떤 책들이 나오는지" 대표 2~3권을 붙여 **AskUserQuestion 객관식**으로 묻는다(복수 선택 허용).
- 예: `[주제] 의사결정·확률 — Thinking in Bets, Thinking, Fast and Slow 쪽` / `[소재] 포커 — 『The Biggest Game in Town』 쪽`
- 사용자가 이미 의도를 말했으면 묻지 않는다. 답이 없거나 사용자가 자리에 없으면 **리뷰·출판사 소개에서 가장 많이 언급된 축**을 기본으로 하고, 그 선택을 결과 subtitle에 적는다.
- 주의: 소재 축은 검색어로 바로 잡혀서 아무 생각 없이 가면 항상 소재로 간다. 주제·형식 축이 사용자 의도인 경우가 많다.

## 2. 단계 1 — 기준 도서 확정
```
python scripts/yes24_lookup.py "블러프"
```
원제·원저자를 확정한다(예: The Biggest Bluff / Maria Konnikova). 이후 모든 소스 검색은 **원제·원저자**로 한다.

## 3. 단계 2 — 소스 수집
축에 맞는 소스를 3종류 이상, 5곳 이상 모은다. 종류: 어워드 / 전문가 추천 / 언론·결산 / 독자 커뮤니티.

| 소스 | 방법 | 잘 맞는 경우 |
|---|---|---|
| Shepherd 유사 도서 | WebSearch `shepherd.com books like "<원제>"` → WebFetch | 논픽션 전반. 저자가 직접 고른 책이라 결이 맞음 |
| Five Books | WebSearch `fivebooks.com <주제어> best books` → 인터뷰 페이지 WebFetch | 주제 축(의사결정, 금융사, 심리) |
| 어워드·랭킹 | `python scripts/award_candidates.py <slug> --seed "<제목>"` (어워드에 없으면 `--genre <장르>`) | 소설·논픽션 수상작. FT Business Book, Pulitzer, Baillie Gifford 등 |
| 언론 결산·전문 목록 | WebSearch로 찾은 목록 페이지 (NYT, Guardian, Economist, 분야 전문가 Top 10) | 고전 확인용 |
| Goodreads 목록 | WebSearch `goodreads list <주제>` → 목록 페이지 | 독자 인기 확인 |
| 커뮤니티 | `python scripts/community_fetch.py <slug> "<원제>" "<주제어 books>"` → HN·Discourse·Lemmy | 비즈니스·기술·논픽션은 HN이 강함 |
| Reddit | `python scripts/gemini_candidates.py <slug> "<원제> (<원저자>)"` | 롱테일. 출처 표기는 `Reddit(Gemini 경유)` |

- 소스마다 **읽은 페이지 URL과 그 페이지에 나온 책(원제·저자)** 을 메모해 둔다. 이게 집계의 원재료다.
- 축이 '주제'면 검색어도 주제어로(`decision making under uncertainty books`), '소재'면 소재어로(`poker nonfiction`). 소재 검색만 하면 소재 목록이 나온다.

## 4. 단계 3 — 집계
- 같은 작품을 **원제 기준**으로 묶는다(부제 차이·영국판/미국판 제목 차이는 같은 책). 시리즈는 대표작 1권.
- 책마다 언급한 소스 이름을 모아 근거 수를 센다. `data/queries/<slug>.rank.json`에 남긴다(예: `seed-tinker.rank.json`).
- Gemini 후보는 다른 소스와 같은 '1곳'이다. Gemini가 말한 언급 횟수는 쓰지 않는다. 없는 책·틀린 저자 가능성이 있으니 원제·저자가 다른 소스나 YES24/Goodreads에서 확인되는 것만 쓴다.

## 5. 단계 4 — 목록 작성 + 단계 확장
### 5.1 순위와 확장
PLAN 6절 '단계 확장 규칙'을 따른다.
1순위(고른 축) → 2순위(같은 주제의 다른 축) → 3순위(같은 저자·형식, 근거 2곳+) → 4순위(국내서, 근거 2곳+ · YES24 평점·판매지수).
국내판이 있는 책이 10권(기본값)이 될 때까지만 내려간다. 국내판 여부는 6절 실행 후에 알 수 있으므로, **처음엔 1·2순위로 30권 정도 쓰고 → build_query → 국내판 수를 보고 → 모자라면 3·4순위를 추가**한다.

### 5.2 파일 형식 `data/queries/<slug>.json`
```json
{
 "query": "블러프",
 "title": "『블러프』를 좋아했다면 — 의사결정·확률 논픽션 25선",
 "subtitle": "축: 주제(불확실성 속 의사결정). 근거: Shepherd, Five Books(…), …, Reddit(Gemini 경유)",
 "books": [
  ["기준 도서", "", "The Biggest Bluff", "마리아 코니코바", "기준 도서", "한두 문장 소개", "The Biggest Bluff", ""],
  ["[1순위] 판단·확률", "", "Thinking in Bets", "애니 듀크", "Five Books · Shepherd · Reddit(Gemini 경유) (3곳)", "추천 포인트", "Thinking in Bets", ""]
 ]
}
```
행 = `[카테고리, 한국어 제목, 원제, 저자(한글), 수상·선정 이력, 추천 포인트, Goodreads 검색어, 비고]`
- **한국어 제목은 비운다.** 스크립트가 원제+저자로 YES24에서 찾는다. 자동으로 못 찾고 사람이 확인한 경우에만 적는다(예: Moral Animal → 「도덕적 동물」, More Money Than God → 「헤지펀드 열전」).
- **저자(한글)는 국내 표기**로. 표기가 여러 가지면 `|`로 나열: `"서배스천 맬러비|세바스찬 말라비"`, `"앨 앨버레즈|알 알바레즈"`. 모르면 YES24에서 저자 검색으로 확인한다.
- 원제는 **정식 전체 제목**이 안전하다(Titan → `Titan: The Life of John D. Rockefeller, Sr.`). 숫자는 그대로(`The 39 Steps`).
- 수상·선정 이력: 확인한 소스 이름 + `(N곳)`. 어워드는 연도·결과까지(`FT 올해의 경영서 2010 수상`).
- 추천 포인트: 기준 도서와 어떻게 이어지는지 1~2문장. 축과의 연결을 쓴다.
- 일본어 원서: 사전 형식 `{"cat":…, "original":"黒牢城", "author":"요네자와 호노부", "lang":"ja", "author_orig":"米澤穂信", …}` (CLAUDE.md 참고).
- 카테고리는 축과 순위가 보이게: `[1순위] 판단·확률`, `[2순위] 포커 논픽션`, `[3순위] 같은 저자`, `[4순위] 국내서`. 미번역은 스크립트가 '미번역 명작'으로 분리한다.

## 6. 단계 5~6 — 국내 정보 부착과 검수
```
python scripts/build_query.py <slug>          # 번역본·eBook·밀리·리디·크레마·평점 + 리뷰 수집
```
- 이전 결과(`<slug>.result.json`)에 `korean`이 있고 원제·저자가 그대로면 재사용한다. **다시 매칭시키려면 result.json의 그 책 `korean`을 지운 뒤** 재실행.
- 검수 순서
  1. `❓ 확인 불가`(API 실패) → 재실행.
  2. `⚠️ 음역 일치`(원제 필드 없는 상품을 저자·음역으로 맞춘 것) → YES24 상품 페이지에서 원제 확인.
  3. `국내판 없음` → 저자 이름으로 YES24 검색해 국내 출간 목록을 본다. 다른 제목으로 나온 경우가 많다(Mastermind → 「생각의 재구성」). 찾으면 행에 한국어 제목을 적고 `korean` 지우고 재실행.
  4. 오매칭 의심(제목이 엉뚱함) → 저자 표기 확인. 과거 사례: The Company↔「청소부 밥」, King of Capital↔씨티그룹 책 — 모두 `matching.py`에서 막았지만 새 유형이 나오면 `matching.py`를 고치고 `python scripts/eval_sheet.py`로 회귀 확인(✅ 수 유지, 오매칭 0).
- 국내판 있는 책이 목표(10권) 미만이면 5.1로 돌아가 다음 순위를 추가.

## 7. 단계 7 — 전달
CLAUDE.md '새 추천 질의 순서' 3~4단계(리뷰 요약, 영상화)를 끝내고 푸시. 사용자에게는:
- 고른 축 한 줄, 지금 바로 읽을 책(구독 포함 여부), 미번역 명작, 확장했다면 몇 순위까지 내려갔는지.

## 8. 사례와 교훈
| 질의 | 한 일 | 잘된 점 | 문제와 교훈 |
|---|---|---|---|
| 물고기는 존재하지 않는다 | 과학 에세이·분류학·회고록 3갈래, 24권 | 형식(과학+회고 에세이)을 살린 갈래 | 축을 묻지 않고 내가 골랐다 → 이제 단계 0에서 묻는다 |
| 문 앞의 야만인들 | HN 커뮤니티 + Shepherd + FT 경영서상 + Gemini, 26권 | HN이 비즈니스 논픽션에서 강함 확인 | **소재(사모펀드)로 치우침.** 사용자는 '월가 내러티브 논픽션'(형식·톤)도 원했을 수 있다. Titan·Mallaby처럼 원제 축약·저자 음역 차이로 놓친 책 → 전체 원제, `|` 변형 |
| 블러프 | Shepherd, Five Books 2개(포커·의사결정), Nolan Dalla Top10, Gemini, HN·Discourse, 26권 | 근거 5종 이상 | **소재(포커)로 감. 의도는 주제(의사결정)였다.** 포커 실전서·포커 소설까지 들어감. 번역서가 적어 확장 규칙 필요 → PLAN 6절 |

## 9. 하지 말 것
- 질의 없이 소스 캐시만으로 목록 만들기(PROGRESS 11절에서 삭제한 이유).
- 한국어 제목 추측 기입, 기억으로 수상 이력 적기.
- Reddit 원문·댓글 수집 시도(Claude 도구·공개 JSON 모두 차단, Gemini 경유만).
- `.env` 값 출력.
