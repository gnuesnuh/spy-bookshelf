# 고정 프롬프트 3 — 목록 고르기 (PLAYBOOK 단계 4)

입력: `<slug>.axes.json`(고른 축) + `<slug>.rank.json`(집계). 사람(Claude) 판단은 **"이 책이 고른 축에 맞나"** 하나뿐이다.

## 절차
1. rank.json 위에서부터 한 권씩 본다. 책마다 아래 중 하나로 판정하고 **이유 한 줄**을 남긴다.
   - `1순위`: 고른 축의 direction에 정확히 맞는다
   - `2순위`: 고른 축은 아니지만 기준 도서의 다른 축(axes.json의 나머지)에 맞는다
   - `3순위`: 같은 원저자, 또는 기준 도서와 같은 형식
   - `제외`: 축에 안 맞음 / 실용서·교재인데 축이 교양 / 실재 확인 안 됨 등 — 이유 필수
   - 모르는 책은 Goodreads·YES24에서 소개를 보고 판정한다. 기억으로 판정하지 않는다.
2. 근거 요건: 1·2순위 1곳 이상, 3·4순위 2곳 이상. 미달이면 제외.
3. 순서: 1순위 → 2순위 → 3순위, 같은 순위 안에서는 rank.json 순서(근거 수) 유지.
4. 개수: 1·2순위로 25~30권. 국내판 수는 build_query 후에 보고 PLAN 6절 확장 규칙을 적용한다(4순위 국내서는 그때 추가).
5. 갈래(카테고리): 1순위 안을 2~4개 갈래로 나눠도 된다. 갈래 이름은 축의 하위 주제(예: "확률적 사고", "판단의 함정").

## 기록
- 판정 전부를 `data/queries/<slug>.picks.json`에 남긴다: `[{original, author, verdict, why, n, sources}]` — 제외한 책도 남긴다(다음 사람이 판단을 검토할 수 있게).
- 목록 `data/queries/<slug>.json`의 행은 사전 형식:
  `{"category": "[1순위] 확률적 사고", "original": ..., "author": "<한글 저자, 변형은 |>", "awards": "<sources를 ' · '로> (N곳)", "summary": "<기준 도서와의 연결 1~2문장>", "grq": "<원제 주제목>", "why": "<판정 이유>"}`
- 한국어 제목(`title`)은 비운다. 한글 저자명은 YES24 저자 검색으로 확인한 표기.
